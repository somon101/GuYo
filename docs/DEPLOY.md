# Запуск GuYo на своём сервере (VPS)

Сервер с нуля: пустая база, никаких данных со старого сервера. Всё, что нужно, лежит в папке `deploy/`.
Админка остаётся на GitHub Pages (ей ничего не нужно на сервере), приложение и админка ходят на новый адрес.

## Что понадобится
- **VPS KVM** (Хостер: Start SSD KVM, 1 ядро, 1 ГБ, 20 ГБ), система **Ubuntu 24.04 LTS** (или 22.04), чистая, без панелей.
- **Домен** и адрес для сервера, например `api.ваш-домен.ru`: у домена в DNS запись типа **A** на IP-адрес сервера. Без домена нет HTTPS, а приложение на телефоне без HTTPS не работает.
- Доступ к серверу по SSH (логин `root` и пароль из письма хостинга).

## Установка (один раз, около 10 минут)
1. Зайти на сервер: `ssh root@IP-АДРЕС`.
2. Скачать проект и запустить установку (подставьте свой адрес):
   ```
   apt-get update && apt-get install -y git
   git clone https://github.com/somon101/GuYo.git /opt/guyo
   bash /opt/guyo/deploy/setup-server.sh api.ваш-домен.ru
   ```
   Скрипт сам: добавит подкачку 2 ГБ (серверу тесно), включит файервол (только 22, 80, 443), автоматические обновления безопасности, поставит Docker, создаст `deploy/.env` со случайными паролями, запустит базу и сервер и включит ночную копию базы.
3. В конце скрипт напишет **логин и пароль админа** (`admin` и случайный пароль). Запишите, потом смените в админке.
4. Проверить: открыть в браузере `https://api.ваш-домен.ru/health`, должно быть `{"status":"ok"}`.

Если репозиторий приватный, `git clone` попросит доступ: используйте ключ развёртывания (deploy key) GitHub. Токены и пароли в чат и в код не вставляйте.

## Подключить админку и приложение
- **Админка:** в `admin-web/.env.production` поменять `VITE_API_URL` на `https://api.ваш-домен.ru` и отправить в `main`: GitHub сам пересоберёт страницу. В `deploy/.env` в `ALLOWED_ORIGINS` должен стоять адрес страницы админки (по умолчанию `https://somon101.github.io`).
- **Приложение:** в настройках репозитория GitHub (Settings → Secrets and variables → Actions → Variables) поменять `API_BASE_URL` на `https://api.ваш-домен.ru` и заново собрать APK.

## Что заполнить в админке с нуля
База пустая: словари и слова, сезон и пропуск, достижения, уведомления и т. д. заводятся в админке (как раньше). При первом запуске сами создаются: админ, 7 рангов, языки, шаблоны.

## Обновление сервера
После каждого обновления кода в `main`: зайти по SSH и выполнить `bash /opt/guyo/deploy/update.sh`. Скрипт делает копию базы, подтягивает код, пересобирает и перезапускает, проверяет, что сервер отвечает. Данные остаются.

## Копии базы
- Каждую ночь (02:17 по Душанбе) делается копия в `deploy/backups/` (хранятся 7 дней), сюда же копируются загруженные файлы.
- **Это тот же диск, что и сервер.** Если сервер сломается, пропадут и данные, и копии. Периодически копируйте папку `deploy/backups/` на другой компьютер или в облако (например `scp root@IP:/opt/guyo/deploy/backups/guyo-*.sql.gz .`). Позже можно автоматизировать.
- Вернуть копию: `bash /opt/guyo/deploy/restore.sh deploy/backups/guyo-ДАТА.sql.gz` (заменяет текущую базу, спросит подтверждение).
- Ручная копия сейчас: `bash /opt/guyo/deploy/backup.sh`.

## Если что-то не работает
- Посмотреть, что с сервером: `cd /opt/guyo/deploy && docker compose ps`.
- Журнал сервера: `docker compose logs --tail=100 backend`; прокси и сертификат: `docker compose logs --tail=100 caddy`.
- Нет сертификата или «не открывается»: проверьте, что запись A у домена указывает на этот сервер и порты 80 и 443 не закрыты у хостинга.
- Сервер падает от нехватки памяти (1 ГБ): `free -h`; подкачка должна быть включена (`swapon --show`). Если падает часто, пора перейти на Optima (2 ГБ): в `deploy/.env` поставить `WEB_CONCURRENCY=2` и поднять настройки базы в `deploy/docker-compose.yml` (`shared_buffers=256MB`, `effective_cache_size=1GB`).

## Устройство
- `db`: PostgreSQL 16, данные в `deploy/data/postgres`, настроен под 1 ГБ памяти.
- `backend`: сервер приложения; при каждом запуске сам обновляет таблицы базы, проверяет начальные данные и стартует один рабочий процесс. Загрузки лежат в `deploy/data/storage`.
- `caddy`: принимает запросы на 80 и 443, сам получает и продлевает сертификат HTTPS и передаёт запросы серверу.
- Логи ограничены (по 3 файла по 10 МБ), чтобы диск не забивался.
