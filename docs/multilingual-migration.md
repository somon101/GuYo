## 1. Решения (утверждены)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Что такое словарь | **Набор понятий.** Направление изучения («родной → изучаемый») — отдельно, у человека |
| 2 | Языки | **ru, tg, uz, en** — все четыре равноправны, «главного» нет |
| 3 | Прогресс, память, уровни, история ответов | **На изучаемый язык.** У каждого языка свой прогресс, можно учить параллельно |
| 4 | Родной язык | Прогресс **не меняет** — только язык вопросов и подсказок |
| 5 | Рейтинг | **Общий на все языки** — один счёт, очки складываются |
| 6 | Достижения | **Есть область применения, выбирается при создании:** «по изучаемому языку» или «общая». По языку — «выучено 10 слов» (10 по русскому ≠ 10 по английскому). Общие — серия дней, друзья, набор очков, пройденные квесты, пройденные уроки: они как рейтинг, на все языки сразу |
| 7 | Фразы | **Вариант 2**: понятие + запись на каждый язык (текст, транскрипция, аудио) |
| 8 | Мини-фразы | Получают **ярлык языка**; показываются только в своём направлении |
| 9 | Стартовые наборы | Сначала **переносятся в новую модель** (это готовый контент: «Набор 500» — 537 фраз в 4 языках, в базе их нет), и **только потом** удаляются файл, эндпоинт и кнопка. Перед удалением — сверить с базой, что ничего не потерялось |
| 10 | ИИ-генератор | **Остаётся** и создаёт материал **сразу для всех языков** (с переводами) |

## 2. Целевая модель данных

```
concepts                          — понятие (смысл), одно на все языки
  id
  category_id      ┐
  importance       │
  role             ├ общая классификация, НЕ дублируется по языкам
  image_key        │
  темы (word_topics → concept_topics)
  created_at / updated_at

word_entries                      — языковая запись (бывшая таблица words)
  id                ← СОХРАНЯЕТ id нынешнего Word (см. §4)
  concept_id        → понятие
  language          → ru / tg / uz / en
  text              ← бывшее word.word
  transcription     ← бывшее word.transcription
  audio_key         ← бывшее word.word_audio_key
  enabled
  created_at / updated_at

word_entry_forms                  — формы (бывшая word_forms)
  id, word_entry_id, language, text        (структура уже подходит ✔)

word_translations                 — УДАЛЯЕТСЯ
  перевод = языковая запись того же понятия на другом языке

phrase_concepts / phrase_entries  — фразы по той же схеме, что слова
  phrase_concepts: id, category_id, темы, image_key
  phrase_entries:  id, phrase_concept_id, language, text, transcription, audio_key

mini_phrases                      — + поле language (ярлык языка)
mini_phrase_parts                 — без изменений: word_entry_id, form_id, role-из-понятия

users                             — + learning_language (изучаемый, явно)
                                    native_language = нынешнее translation_language
                                      (в интерфейсе отдельного «языка перевода» больше нет —
                                       есть «родной язык» и «язык для изучения»)
```

Для **существующих людей** перенос без вопросов: **родной** ← их нынешний `translation_language`, **изучаемый** ← язык словаря, который они изучают.

Ключевое: **слова, фразы и мини-фразы устроены одинаково** — понятие + записи по языкам.

## 3. Что переиспользуется без переделки

| Уже готово | Почему |
|---|---|
| Переводы с **собственным аудио** (`word_translations.audio_key`) | становится `audio_key` языковой записи |
| **Формы по языкам** (`word_forms.language`) | структура уже правильная |
| Прогресс и история (`word_progress`, `word_attempt`) | привязаны к записи → у каждого языка свой прогресс **само собой** |
| Память (FSRS), приоритет, уровни | работают с записью, язык им безразличен |
| Рейтинг | уже общий на человека, менять нечего |
| Категории, темы, важность, роль | уже общие — переезжают на понятие |

**Вывод: это перестройка структуры, а не наполнение контента заново.** Для «Человек» уже лежат ru «Человек» (+аудио, +формы), tg «одам» (+аудио, +форма «одамон»), uz «Odam», en «person» — то есть записи четырёх языков фактически существуют.

## 4. Миграция данных

**Главное правило: русская запись сохраняет `id` нынешнего слова.** Тогда прогресс, память, уровни, история ответов, рейтинг и достижения продолжают работать **без единого изменения** — они ссылаются на тот же id.

| Шаг | Что делает |
|---|---|
| 1 | Каждый `Word` → `concept` (переносим категорию, важность, роль, картинку, темы) |
| 2 | Каждый `Word` → `word_entry` с `language = dictionary.language`, **тем же id**, переносим `word`, `transcription`, `word_audio_key` |
| 3 | Все `WordForm` → `word_entry_forms` (**id сохраняем**) |
| 4 | Каждый `WordTranslation` → `word_entry` того же понятия: `text` ← перевод, `audio_key` ← аудио перевода, `language` ← язык перевода, транскрипция пустая |
| 5 | Существующие формы этого языка привязываем к новой записи |
| 6 | `Phrase` → `phrase_concept` + `phrase_entry` (язык словаря) + записи из переводов; аудио — в свою запись |
| 7 | `MiniPhrase` → проставляем `language = dictionary.language` |
| 8 | `users` → `learning_language` из словаря, который человек изучает |

**Проверки после миграции:** 2278 понятий; записей не меньше 2278; ни одной потерянной формы, аудио и перевода; у всех 779 мини-фраз есть язык; у 947 фраз есть записи; прогресс всех людей на месте.

## 7. Риски и что нужно до старта

| Риск | Как закрываем |
|---|---|
| Потеря прогресса людей | правило §4: русская запись сохраняет id; проверка после миграции |
| Дубли или потери контента | перенос идемпотентный, с отчётом по каждой таблице |
| Долгая остановка сервиса | миграция структуры быстрая, перенос данных — отдельным шагом; читатели переключаются после проверки |
| Половинчатое состояние в приложении | приложение не трогаем до этапа 7, пока бэкенд не готов |
| Нет стенда для проверки | **нужна копия боевой базы** (этап 0) — иначе проверять миграцию негде |

**Сколько это по объёму:** это самая крупная перестройка проекта — затрагивает базу, весь бэкенд, админку и приложение. Делается этапами, каждый этап проверяем отдельно.
